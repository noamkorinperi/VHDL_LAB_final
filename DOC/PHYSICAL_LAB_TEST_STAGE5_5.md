# תוכנית בדיקת מעבדה פיזית — שלב 5.5

עודכן: 17.08.2026 23:06 IDT

מטרת הבדיקה היא לאמת על כרטיס DE10-Standard את שרשרת ה־clock/reset, מיפוי
הפינים, קריאת KEY1–KEY3 לאחר debounce ויציאת ה־PWM. זו בדיקת חומרה מוקדמת;
מסלול הפסיקות המלא ו־SignalTap ייבדקו בהמשך.

## מה כבר מוכן

- כל פיני `CLOCK_50`, ‏`KEY`, ‏`SW`, ‏`LEDR` ו־`HEX0`–`HEX5` מוגדרים ב־QSF.
- שעון הליבה הוא 20 MHz וה־Divider נשאר על 50 MHz.
- debounce פיזי הוא 200,000 מחזורים, כלומר 10 ms ב־20 MHz.
- תוכנת `ITCM_stage5_5.hex` כבר משובצת בתכן.
- Quartus Map, Fitter, Assembler ו־Timing Analyzer עברו. ה־setup slack הגרוע
  ביותר הוא חיובי: 2.631 ns; קובץ ה־SOF כבר קיים מקומית.
- אותו קובץ `ITCM_stage5_5.hex` עבר גם בדיקת preflight אוטומטית ב־ModelSim:
  `STAGE 5.5 SMOKE FIRMWARE PASS`.

## התנהגות צפויה של תוכנת הבדיקה

| רכיב בכרטיס | התנהגות |
|---|---|
| `HEX0` | מציג `C`, כדי להוכיח שהתוכנה התחילה לרוץ |
| `HEX1`–`HEX5` | מציגים `0` |
| `LEDR0` | דולק כל עוד KEY1 לחוץ לאחר debounce |
| `LEDR1` | דולק כל עוד KEY2 לחוץ לאחר debounce |
| `LEDR2` | דולק כל עוד KEY3 לחוץ לאחר debounce |
| `LEDR8` | יציאת PWM; ה־duty נשלט על ידי `SW7:0` |
| `LEDR9` | דולק כל עוד לפחות אחד מ־KEY1–KEY3 לחוץ |
| `KEY0` | reset פעיל־נמוך |

תדר ה־PWM הוא כ־76.3 Hz. במצב הנוכחי ערך switch קטן נותן זמן HIGH גדול:

| `SW7:0` | duty HIGH צפוי בקירוב | מה רואים ב־LEDR8 |
|---:|---:|---|
| `0` | כמעט 100% | בהיר מאוד |
| `64` | 75% | בהיר |
| `128` | 50% | בינוני |
| `192` | 25% | חלש |
| `255` | כמעט 0% | כמעט כבוי |

## חלק א — פתיחת הפרויקט וטעינת הכרטיס

1. חבר את ספק הכוח ואת כבל USB-Blaster לכרטיס והדלק אותו.
2. פתח ב־Quartus את:

   ```text
   C:/Users/noam1/Desktop/VHDL Lab/Final proj/Quartus/RV32IMscMCU/RV32IMscMCU.qpf
   ```

3. ודא שה־Top-Level הוא `RV32IMscMCU` ושהרכיב הוא
   `5CSXFC6D6F31C6`.
4. אין חובה לקמפל שוב: קובץ התכנות המוכן הוא:

   ```text
   output_files/RV32IMscMCU.sof
   ```

5. פתח `Tools > Programmer`.
6. ב־`Hardware Setup` בחר `USB-Blaster`.
7. אם הקובץ אינו מופיע, לחץ `Add File` ובחר את ה־SOF לעיל.
8. סמן `Program/Configure` ולחץ `Start`. ההתקדמות צריכה להגיע ל־100% ללא
   error.

## חלק ב — בדיקת אתחול ו־reset

1. מיד לאחר הצריבה ודא ש־HEX0 מציג `C`.
2. לחץ והחזק KEY0. בזמן reset כל LED צריך להיות כבוי ותצוגות ה־HEX חוזרות
   לערך האיפוס.
3. שחרר KEY0. לאחר נעילת ה־PLL, ‏HEX0 צריך לחזור ל־`C`.
4. אם HEX0 אינו חוזר ל־`C`, עצור וצלם את הכרטיס ואת חלון Programmer.

## חלק ג — בדיקת KEY1–KEY3

בצע לכל כפתור בנפרד:

1. לחץ מעל 20 ms.
2. ודא שה־LED המתאים (`LEDR0`, ‏`LEDR1` או `LEDR2`) ו־`LEDR9` נדלקים.
3. החזק את הכפתור כשנייה: המצב צריך להישאר יציב ללא הבהוב.
4. שחרר: שני ה־LEDs צריכים להיכבות לאחר זמן debounce קצר.
5. בצע לחיצה קצרה אך מכוונת. לחיצה קצרה מ־10 ms רשאית להידחות; לחיצה
   יציבה מעל 10 ms חייבת להיקלט.
6. לחץ שני כפתורים יחד וודא ששני ה־LEDR המתאימים דולקים ו־LEDR9 נשאר דולק.

## חלק ד — בדיקת PWM

1. קבע `SW7:0=0` והסתכל על LEDR8.
2. עבור לפי הסדר לערכים `64`, ‏`128`, ‏`192`, ‏`255` והשווה את עוצמת האור
   לטבלה.
3. בכל ערך המתן לפחות שנייה כדי להבחין בעוצמה/הבהוב.
4. אם יש oscilloscope או logic analyzer ונקודת מדידה בטוחה, מדוד כ־76 Hz
   ו־duty של כ־50% כאשר `SW7:0=128`. אל תחבר probe ישירות אם אין נקודת
   גישה בטוחה בלוח.

## שער יציאה

שלב 5.5 יעבור רק אם הצריבה מגיעה ל־100%, reset מפעיל מחדש את התוכנה, כל
שלושת הכפתורים מזוהים נכון, ו־LEDR8 משתנה באופן עקבי עם ערך ה־switches.
בכשל אין להמשיך לבדיקת פסיקות על הכרטיס; יש לשלוח צילום ותיאור הסעיף שנכשל.
